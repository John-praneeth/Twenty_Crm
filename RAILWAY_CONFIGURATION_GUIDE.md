## Required Services Configuration

### Service 1: PostgreSQL Database

**How to Add:**
1. In your Railway project, click **"+ New"**
2. Select **"Database"** → **"Add PostgreSQL"**
3. Railway will auto-provision PostgreSQL 16

**Configuration:**
- Version: `postgres:16`
- No additional configuration needed
- Railway auto-creates: `DATABASE_URL`, `PGHOST`, `PGPORT`, `PGUSER`, `PGPASSWORD`, `PGDATABASE`

**Environment Variables (Auto-created):**
```bash
POSTGRES_DB=railway
POSTGRES_USER=postgres
POSTGRES_PASSWORD=<auto-generated>
PGDATA=/var/lib/postgresql/data/pgdata
```

---

### Service 2: Redis Cache

**How to Add:**
1. Click **"+ New"**
2. Select **"Database"** → **"Add Redis"**
3. Railway will auto-provision Redis 8.x

**Configuration:**
- Version: `redis:8.2.1` or latest
- No additional configuration needed
- Railway auto-creates: `REDIS_URL`, `REDIS_PASSWORD`

**Environment Variables (Auto-created):**
```bash
REDIS_PASSWORD=<auto-generated>
REDIS_URL=redis://default:<password>@<host>:<port>
```

---

### Service 3: Twenty Server (Main Application)

**How to Add:**
1. Click **"+ New"**
2. Select **"GitHub Repo"**
3. Choose your Twenty CRM repository
4. Configure as shown below

**Service Settings:**

| Setting | Value |
|---------|-------|
| **Service Name** | `twenty-server` or `twenty` |
| **Source** | GitHub Repository |
| **Branch** | `main` (or your default branch) |
| **Root Directory** | `/` (leave empty) |
| **Builder** | Dockerfile |
| **Dockerfile Path** | `packages/twenty-docker/twenty/Dockerfile` |
| **Watch Paths** | (leave default) |

**Build & Deploy Configuration:**

Go to **Settings** → **Deploy**

| Setting | Value |
|---------|-------|
| **Build Command** | (auto-detected from Dockerfile) |
| **Custom Start Command** | (leave empty - uses Dockerfile CMD) |
| **Health Check Path** | `/healthz` |
| **Health Check Timeout** | `100` seconds |
| **Restart Policy** | `On Failure` |

**Networking:**

Go to **Settings** → **Networking**
1. Click **"Generate Domain"** to get a public URL
2. Note your domain (e.g., `your-app.up.railway.app`)

**Environment Variables:**

Go to **Variables** tab and add these:

```bash
# Core Application Settings
PORT=3000
SERVER_URL=${{RAILWAY_PUBLIC_DOMAIN}}
APP_SECRET=<generate-random-32-char-string>

# Database Connection (reference the Postgres service)
PG_DATABASE_URL=${{Postgres.DATABASE_URL}}

# Redis Connection (reference the Redis service)
REDIS_URL=${{Redis.REDIS_URL}}

# Server-Specific Settings (IMPORTANT!)
DISABLE_DB_MIGRATIONS=false
DISABLE_CRON_JOBS_REGISTRATION=false

# Storage Configuration
STORAGE_TYPE=local
STORAGE_LOCAL_PATH=.local-storage

# Optional: If using S3 storage (recommended for production)
# STORAGE_TYPE=s3
# STORAGE_S3_REGION=us-east-1
# STORAGE_S3_NAME=your-bucket-name
# STORAGE_S3_ENDPOINT=https://s3.amazonaws.com
# STORAGE_S3_ACCESS_KEY_ID=<your-access-key>
# STORAGE_S3_SECRET_ACCESS_KEY=<your-secret-key>
```

**How to Add:**
1. Click **"+ New"**
2. Select **"GitHub Repo"**
3. Choose **the same** Twenty CRM repository
4. Configure as shown below

**Service Settings:**

| Setting | Value |
|---------|-------|
| **Service Name** | `twenty-worker` |
| **Source** | GitHub Repository (same as server) |
| **Branch** | `main` (same as server) |
| **Root Directory** | `/` (leave empty) |
| **Builder** | Dockerfile |
| **Dockerfile Path** | `packages/twenty-docker/twenty/Dockerfile` |

**Build & Deploy Configuration:**

Go to **Settings** → **Deploy**

| Setting | Value |
|---------|-------|
| **Build Command** | (auto-detected from Dockerfile) |
| **Custom Start Command** | `yarn worker:prod` ⚠️ **CRITICAL!** |
| **Restart Policy** | `On Failure` |

⚠️ **IMPORTANT**: The worker MUST have a custom start command set to `yarn worker:prod`

**Networking:**

- **DO NOT** generate a public domain for the worker
- Worker doesn't need external access

**Environment Variables:**

Go to **Variables** tab and add these:

```bash
# Core Application Settings (must match server)
SERVER_URL=${{twenty-server.RAILWAY_PUBLIC_DOMAIN}}
APP_SECRET=<same-as-server-EXACTLY>

# Database Connection (reference the Postgres service)
PG_DATABASE_URL=${{Postgres.DATABASE_URL}}

# Redis Connection (reference the Redis service)
REDIS_URL=${{Redis.REDIS_URL}}

# Worker-Specific Settings (CRITICAL - DIFFERENT FROM SERVER!)
DISABLE_DB_MIGRATIONS=true
DISABLE_CRON_JOBS_REGISTRATION=true

# Storage Configuration (must match server)
STORAGE_TYPE=local
STORAGE_LOCAL_PATH=.local-storage

# Optional: If using S3 storage (must match server)
# STORAGE_TYPE=s3
# STORAGE_S3_REGION=us-east-1
# STORAGE_S3_NAME=your-bucket-name
# STORAGE_S3_ENDPOINT=https://s3.amazonaws.com
# STORAGE_S3_ACCESS_KEY_ID=<your-access-key>
# STORAGE_S3_SECRET_ACCESS_KEY=<your-secret-key>
```

## Critical Configuration Notes

### 1. APP_SECRET Generation

The `APP_SECRET` must be:
- **Exactly the same** for both Server and Worker
- A secure random 32+ character string
- Never changed after initial setup (will invalidate sessions)

**Generate it:**

```bash
# Option 1: Using OpenSSL (Mac/Linux)
openssl rand -hex 32

# Option 2: Using Node.js
node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"

# Option 3: Using Python
python3 -c "import secrets; print(secrets.token_hex(32))"

# Option 4: Online
# Visit: https://www.random.org/strings/
```

**Example output:** `a7f4e9c2d8b3f6a1e5c7d9b2f4a6e8c0d2f4a6e8c0d2f4a6e8c0d2f4a6e8c0`

### 2. Database Migrations

| Service | DISABLE_DB_MIGRATIONS | Why? |
|---------|----------------------|------|
| **Server** | `false` | Server handles DB setup and migrations |
| **Worker** | `true` | Prevents conflicts - only server should migrate |

### 3. Cron Jobs Registration

| Service | DISABLE_CRON_JOBS_REGISTRATION | Why? |
|---------|-------------------------------|------|
| **Server** | `false` | Server registers scheduled jobs |
| **Worker** | `true` | Prevents duplicate job registration |

### 4. Service References

Railway uses the syntax `${{ServiceName.VARIABLE_NAME}}` to reference variables between services.

**Examples:**
```bash
# Reference Postgres service
PG_DATABASE_URL=${{Postgres.DATABASE_URL}}

# Reference Redis service
REDIS_URL=${{Redis.REDIS_URL}}

# Reference another service's domain
SERVER_URL=${{twenty-server.RAILWAY_PUBLIC_DOMAIN}}

# Use Railway's automatic domain
SERVER_URL=${{RAILWAY_PUBLIC_DOMAIN}}
```

### 5. Storage Configuration

**For Testing/Development:**
```bash
STORAGE_TYPE=local
STORAGE_LOCAL_PATH=.local-storage
```

**For Production (Recommended):**
```bash
STORAGE_TYPE=s3
STORAGE_S3_REGION=us-east-1
STORAGE_S3_NAME=your-bucket-name
STORAGE_S3_ENDPOINT=https://s3.amazonaws.com
STORAGE_S3_ACCESS_KEY_ID=AKIA...
STORAGE_S3_SECRET_ACCESS_KEY=...
```

⚠️ **Note**: For workflows to work properly, you need S3-compatible storage because both Server and Worker need access to the same files.

## Deployment Order & Dependencies

Deploy in this order to avoid errors:

1. ✅ **PostgreSQL** (no dependencies)
2. ✅ **Redis** (no dependencies)
3. ✅ **Twenty Server** (depends on: PostgreSQL + Redis)
4. ✅ **Twenty Worker** (depends on: PostgreSQL + Redis + Server)

Railway handles dependencies automatically when you use `${{ServiceName.VARIABLE}}` syntax.

## Step-by-Step Deployment Process

### Step 1: Prepare Your Repository

Make sure your Twenty CRM code is pushed to GitHub with:
- `packages/twenty-docker/twenty/Dockerfile` exists
- `packages/twenty-server/package.json` has correct scripts

### Step 2: Add Database Services

1. Go to your Railway project dashboard
2. Add PostgreSQL (click + New → Database → PostgreSQL)
3. Add Redis (click + New → Database → Redis)
4. Wait for both to be healthy (green status)

### Step 3: Configure Twenty Server

1. Click **"+ New"** → **"GitHub Repo"**
2. Select your Twenty CRM repository
3. Service will be created - go to **Settings**

**Settings → Build:**
- Set **Dockerfile Path**: `packages/twenty-docker/twenty/Dockerfile`

**Settings → Deploy:**
- Set **Health Check Path**: `/healthz`
- Set **Health Check Timeout**: `100`

**Settings → Networking:**
- Click **"Generate Domain"**
- Copy your domain URL

**Variables:**
- Add all Server environment variables listed above
- Make sure to generate and use a secure `APP_SECRET`

4. Click **"Deploy"** (or wait for auto-deploy)

### Step 4: Configure Twenty Worker

1. Click **"+ New"** → **"GitHub Repo"**
2. Select **the same** Twenty CRM repository
3. Service will be created - go to **Settings**

**Settings → Build:**
- Set **Dockerfile Path**: `packages/twenty-docker/twenty/Dockerfile`

**Settings → Deploy:**
- ⚠️ **Set Custom Start Command**: `yarn worker:prod`
- Set **Restart Policy**: `On Failure`

**Variables:**
- Add all Worker environment variables listed above
- Use the **SAME** `APP_SECRET` as the server
- Set `DISABLE_DB_MIGRATIONS=true`
- Set `DISABLE_CRON_JOBS_REGISTRATION=true`

4. Click **"Deploy"** (or wait for auto-deploy)

### Step 5: Monitor Deployment

1. **Check Server Logs:**
   - Click on Twenty Server → **Deployments** → View latest deployment
   - Look for: `Successfully migrated DB!`
   - Look for: `Application is running on: http://[::]:3000`
   - Look for health check passing

2. **Check Worker Logs:**
   - Click on Twenty Worker → **Deployments** → View latest deployment
   - Look for: `Worker started successfully`
   - No errors about database connections

3. **Check Service Health:**
   - All services should show green/healthy status
   - Server should respond at `/healthz` endpoint

### Step 6: Access Your Application

1. Open your Railway domain (e.g., `https://your-app.up.railway.app`)
2. You should see the Twenty CRM login/signup page
3. Create your account and start using Twenty!

## Troubleshooting Common Issues

### Issue 1: Server Won't Start

**Symptoms:**
- Logs show database connection errors
- Service keeps restarting

**Solutions:**
1. ✅ Verify PostgreSQL service is running (green)
2. ✅ Check `PG_DATABASE_URL=${{Postgres.DATABASE_URL}}`
3. ✅ Check Redis service is running (green)
4. ✅ Check `REDIS_URL=${{Redis.REDIS_URL}}`
5. ✅ Increase health check timeout to 100+ seconds
6. ✅ Check logs for specific error messages

### Issue 2: Worker Won't Start

**Symptoms:**
- Worker logs show "command not found"
- Worker keeps crashing

**Solutions:**
1. ✅ Verify custom start command is set: `yarn worker:prod`
2. ✅ Check `DISABLE_DB_MIGRATIONS=true` (worker-specific)
3. ✅ Check `DISABLE_CRON_JOBS_REGISTRATION=true` (worker-specific)
4. ✅ Verify `APP_SECRET` matches the server exactly
5. ✅ Check database and Redis connections

### Issue 3: Database Migration Errors

**Symptoms:**
- Logs show "migration failed"
- Schema errors in logs

**Solutions:**
1. ✅ Ensure ONLY the server has `DISABLE_DB_MIGRATIONS=false`
2. ✅ Worker must have `DISABLE_DB_MIGRATIONS=true`
3. ✅ Check PostgreSQL disk space
4. ✅ Try redeploying the server service
5. ✅ Check for conflicting migrations

### Issue 4: "yarn: command not found"

**Symptoms:**
- Worker shows "yarn: command not found"

**Solutions:**
1. ✅ The Dockerfile should install yarn automatically
2. ✅ Verify Dockerfile path is correct
3. ✅ Check build logs for yarn installation
4. ✅ Try rebuilding the service

### Issue 5: Environment Variables Not Loading

**Symptoms:**
- App behaves as if env vars are missing
- Connection errors despite correct setup

**Solutions:**
1. ✅ Verify reference syntax: `${{ServiceName.VARIABLE}}`
2. ✅ Check service names match exactly (case-sensitive)
3. ✅ Redeploy after adding new variables
4. ✅ Check for typos in variable names

### Issue 6: Server Unhealthy / Health Check Failing

**Symptoms:**
- Railway shows service as unhealthy
- Deployment says "Health check failed"

**Solutions:**
1. ✅ Increase health check timeout to 100 seconds
2. ✅ Verify health check path is `/healthz`
3. ✅ Check server logs for startup errors
4. ✅ Ensure port is set to `3000` or `$PORT`
5. ✅ Wait longer - first deploy can take 5-10 minutes
